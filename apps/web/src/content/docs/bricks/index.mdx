**Add a brick, get a feature.** Each one contributes a capability to the request context, fully
typed — and leaving it out makes using it a compile error rather than a crash at 3am.

Every page below answers the same questions in the same order: what it installs, what files and
tables it creates, what endpoints it adds, and what it cannot do. If a brick has no endpoints,
its page says so rather than omitting the section.

<Aside type="note" title="Bricks are not middleware">
  CORS, rate limiting, compression and security headers ship **in core** as
  [middleware](/docs/reference/middleware/), because they wrap a request rather than add a
  capability. A brick is the other thing: it puts something new on the context.
</Aside>

## Writing your own

The brick contract is small and public — see [Writing a brick](/docs/reference/bricks/) for the
interface and how types flow. A third-party brick is a normal npm package that exports a factory function;
nothing about the first-party ones is privileged.
