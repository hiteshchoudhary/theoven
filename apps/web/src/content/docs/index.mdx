## Add a config. Get a working feature.

<Tabs>
<TabItem label="Config">
```ts title="oven.config.ts"
import { defineConfig } from '@theoven/core'

export default defineConfig({
  routes:  { dir: './src/routes' },
  db:      { driver: 'postgres', url: process.env.DATABASE_URL },
  auth:    { providers: ['github', 'google'] },
  storage: { driver: 's3', bucket: 'uploads' },
  mail:    { driver: 'resend' },
  queue:   { driver: 'redis' },
})
```
</TabItem>
<TabItem label="Route">
```ts title="src/routes/users/[id]/avatar.post.ts"
import { z } from 'zod'

export const auth   = true
export const params = z.object({ id: z.uuid() })
export const body   = z.object({ file: z.file() })

export default async ({ params, body, user, storage, db, queue }) => {
  const { url } = await storage.upload(`avatars/${params.id}`, body.file)
  await queue.dispatch('resize-avatar', { url })
  return db.user.update(params.id, { avatar: url })
}
```
</TabItem>
</Tabs>

That route is validated, authenticated, typed, and documented at `/docs`. There is no wiring,
no `app.use()`, and nothing to forget.

## What you never install again

Express made you assemble a working server from parts. That was never a choice — it was
homework. These are core behaviour in Oven: always on, correctly ordered, zero configuration.

<CardGrid>
  <Card title="Body parsing" icon="document">
    `ctx.body`, content-type aware, size-limited, and lazy — a route that never reads it never
    parses it. Replaces `body-parser`.
  </Card>
  <Card title="File uploads" icon="upload">
    Uploads arrive as web `File` objects, streamed rather than buffered, with size and MIME
    limits. Replaces `multer`.
  </Card>
  <Card title="Cookies" icon="approve-check">
    `ctx.cookies` with secure defaults and signing built in. Replaces `cookie-parser`.
  </Card>
  <Card title="Token capture" icon="seti:lock">
    `ctx.token`, pulled from the `Authorization` header, a cookie, or the query string — even
    with no auth plugin installed. Replaces the snippet everyone rewrites.
  </Card>
  <Card title="Async errors" icon="error">
    A thrown error becomes an RFC 9457 response whether it was thrown synchronously or not.
    Replaces `express-async-errors`.
  </Card>
  <Card title="Graceful shutdown" icon="rocket">
    SIGTERM drains in-flight requests and closes resources. Mid-drain requests get a `503` with
    `Retry-After`, not a dropped connection.
  </Card>
</CardGrid>

## How it compares

<div class="comparison">

|                                   | Express | Fastify | NestJS  | FastAPI | **Oven** |
| --------------------------------- | :-----: | :-----: | :-----: | :-----: | :------: |
| Runtime                           |  Node   |  Node   |  Node   | Python  | **Bun**  |
| Auth / DB / queue / mail / S3     |    ✗    |    ✗    | partial | partial |  **✓**   |
| Automatic OpenAPI                 |    ✗    | plugin  | plugin  |    ✓    |  **✓**   |
| Types inferred from schemas       |    ✗    | partial | partial |    ✓    |  **✓**   |
| File-based routing                |    ✗    |    ✗    |    ✗    |    ✗    |  **✓**   |
| Body/cookies/uploads always on    |    ✗    | partial |    ✓    |    ✓    |  **✓**   |

</div>

We are not competing on router microseconds — Bun makes everything fast. We compete on the time
between `bun create` and an app shaped like production.

## Built for 2026, not 2014

Oven has no Express compatibility layer, no `(req, res, next)`, no Connect middleware, no
CommonJS build, and no callbacks. Web standards, ESM, and async only.

Every framework that shipped an Express shim ended up shaped by Express. If you want Express,
Express is right there — and it is very good at being Express.
